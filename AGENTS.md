## Repository Overview

**"Birthday Clip Studio"** — a small single-app Flask website that turns a user's
face photo into a finished birthday-clip video. The user uploads a photo in the
browser, positions their face against guide lines (auto-snapped with face
detection), clicks **Generate Video**, and the server renders a two-phase OpenCV
pipeline (face-over-background overlay, then brightness-matte composite) into
`final.mp4` with live progress polling. Deployed on Render with gunicorn.

The browser exports a clipped 112×168 RGBA `face.png` (canvas), POSTs it to the
server; the server renders `bg_preview` (phase 2) then `final.mp4` (phase 3)
using fixed assets (`BG.mp4`, `fg_preview.mp4`, and a fixed tracking JSON).

**Documented** in `README.md` (setup, verify, tuning, deployment) and `Plan.md`
(design notes; partially stale — see Known Inconsistencies).

## Architecture

### Main Entry Points

- **HTTP entry**: `app.py` — Flask app `app` (module-level; gunicorn target is `app:app`)
- **Process entry**: `app.py __main__` block (dev) or `Procfile` gunicorn (prod)
- **Render entry points**: `services/overlay.py::render_bg_preview()` (phase 2),
  `services/composite.py::render_final()` (phase 3)

### Runtime Flows

**Full render flow (user → final.mp4):**

```
Browser (templates/index.html)
  upload photo → FileReader → <image> inside #faceSvg (viewBox 112×168)
  → face-api detects face (tinyFaceDetector + landmarks), snapTransform() aligns
    eyes/mouth to guide lines (sliders zoom/moveX/moveY/rotate)
  → user fine-tunes (sliders, step buttons, drag on #faceOvalHit, wheel zoom)
  → Generate click: primeAutoplay() (iOS sound unlock, synchronous in gesture)
  → getFacePngBlob(): canvas 112×168, clip via Path2D of #faceClip path,
    cover-fit + rotate about center → PNG blob → POST /generate (multipart "face")
  → poll GET /api/progress/<job_id> every 500 ms → progress bar + ETA
  → status "done" → GET /api/result/<job_id> → blob → <video> + Download button

Server (app.py)
  POST /generate
    - checks "face" field present; MAX_CONTENT_LENGTH 20 MB → 413
    - single-active-render gate (status in {"starting","rendering"}) → 429
    - saves uploads/<job_id>_face.png; PNG magic-byte check → 400
    - registers job under jobs_lock BEFORE thread start → 202 {job_id}
    - daemon thread _run_render(job_id, face_png, bg_preview, final_video)
  _run_render (never raises; failures go into the job record)
    - overlay.render_bg_preview(face_png, config.TRACKING_JSON, config.BG_VIDEO,
        bg_preview, tmp_dir, progress_callback)         → phase "overlay" 0–25%
    - composite.render_final(bg_preview, config.FG_VIDEO, final_video, tmp_dir,
        progress_callback)                               → phase "composite" 40–90%
    - status "done", percent 100; delete face_png + bg_preview
    - on exception: status "error" + message, delete all three files
  GET /api/progress/<job_id>  → {status, phase, frame, total, percent, eta, error} (404 unknown)
  GET /api/result/<job_id>    → 409 while rendering / 500 on error / 200 video bytes
                               (file deleted and job removed after serving)
```

**Render internals (phase 2 — `services/overlay.py`):**

- `_load_tracking()` reads `track_result.json` with `encoding="utf-8-sig"` (the file
  has a UTF-8 BOM — **Documented**), accepts `data["faces"][0]["frames"]` or
  `data["frames"]`, returns `{int(frame): item}`.
- `render_bg_preview()` opens `BG.mp4` with cv2.VideoCapture, reads its fps/size/
  frame count, requires the face PNG to be 4-channel RGBA, and for each frame whose
  number is in the tracking dict, calls `_overlay()` (skip if `opacity <= 0`).
- `_overlay()`: resize to (w·scaleX/100, h·scaleY/100), rotate by **`-rotation`**
  (OpenCV CCW vs AE CW sign flip — **Documented** as intentional), alpha-composite
  with opacity; early-out when fully off-screen.
- Writes frames with `cv2.VideoWriter("mp4v")` to `<base>_temp.mp4`, then
  `media.remux_audio(temp_video, bg_video, output_video)` to add AAC audio.
  Temp file deleted in `finally`.

**Render internals (phase 3 — `services/composite.py`):**

- Reads bg (`bg_preview`) + fg (`fg_preview.mp4`) simultaneously; per frame:
  - brightness matte: `alpha = clip((max(fg,axis=2) − BLACK_CUTOFF) / FEATHER_RANGE, 0, 1)`
  - Gaussian blur alpha (`BLUR_KERNEL`), erode (`ERODE_KERNEL`, `ERODE_ITERATIONS`) to kill halo, blur again
  - un-multiply black contamination: `fg_clean = fg / max(alpha, ALPHA_SAFE)`
  - `result = fg_clean·α + bg·(1−α)`
- Same mp4v temp + ffmpeg remux pattern as phase 2.

**Audio remux (both phases — `services/media.py::remux_audio()`):**

- `ffmpeg -y -i temp.mp4 -i <audio source> -c:v libx264 -preset fast -crf 23
  -c:a aac -map 0:v:0 -map 1:a:0 -shortest [-movflags +faststart]
  -progress pipe:1 -nostats <output>`
- Parses `out_time_us=` progress lines live; invokes `remux_progress(frac)` gated
  by duration; raises `RuntimeError` with last 2000 stderr chars on non-zero exit.
- `probe_video()` returns `(width, height, fps)` via ffprobe (used for verification).

**Progress/ETA model (app.py):**

- Percent ranges from `config.PHASE_2_WEIGHT = (0, 25)` and
  `config.PHASE_3_WEIGHT = (40, 90)`; phase-2 audio remux glides 25→40
  (`remux_target=PHASE_3_WEIGHT[0]`), final remux glides 90→100.
- `_make_progress_callback(job_id, phase, lo, hi, remux_phase, remux_target)`
  maps service callbacks onto the job percent range; remux with
  `remux_target=None` holds at `hi`.
- `_update_job()` keeps `eta_history` of `(time, percent)` points (window
  30 s `ETA_HISTORY_WINDOW`, max 200 `ETA_HISTORY_MAX`), cleared when phase changes.
- `_estimate_eta()` least-squares fit of recent points (timestamps centered to
  avoid catastrophic float cancellation); returns None with < 3 points, frozen
  percent, or non-positive slope; clamps to 0–3600 s.
- UI labels: `PHASE_LABELS` in index.html maps phase → text; `formatEta()` rounds
  to 5 s granularity.

**Job lifecycle (app.py):**

- `jobs` dict guarded by `jobs_lock`; record fields: `status, phase, frame, total,
  percent, error, final_video, eta_history`. Statuses: `starting → rendering →
  done | error`.
- `MAX_JOBS = 20`: `_evict_old_jobs_locked()` evicts oldest done/error jobs and
  deletes their final videos.
- `MAX_ACTIVE_RENDERS = 1`: concurrent `POST /generate` → HTTP 429 with
  `RENDER_BUSY_MESSAGE`. **Documented** (README): never raise this without moving
  job state to shared storage (Redis) — the registry is in-process memory, and
  Render must run exactly one gunicorn worker.
- If the thread fails to start, the job is removed (otherwise the busy check would
  429-reject every later render forever).
- Server restart wipes `uploads/` + `tmp/` (startup block in `app.py __main__`).

- Render pipeline code → `services/` (one module per pipeline phase + shared media helpers).
- Paths, video spec, tuning knobs, ffmpeg settings → `config.py` only.
- HTTP routes, job registry, threading, logging → `app.py`.
- All page markup/CSS/JS → `templates/index.html` (single file; no external JS/CSS files).
- Static assets → `static/`; read-only pipeline inputs → `assets/`; runtime
  artifacts → `uploads/` (user files), `tmp/` (intermediates). Both gitignored
  and wiped at startup.
- Temp files: `<jobid>_face.png` in uploads; `<jobid>_bg_preview.mp4`,
  `<jobid>_final.mp4` in tmp; OpenCV intermediates `<base>_temp.mp4` in tmp
  (unique per job so concurrent renders cannot collide — **Documented**).

## Coding Conventions

### Python (app.py, config.py, services/)

- Module + function docstrings describing responsibility and adaptation lineage
  (e.g. overlay.py/composite.py note they were "Adapted from `phase 2 Put tracking
  in bg/...`" — original pipeline scripts lived outside this repo).
- Private helpers prefixed `_` (`_load_tracking`, `_overlay`, `_update_job`,
  `_estimate_eta`, `_evict_old_jobs_locked`, `_make_progress_callback`,
  `_run_render`, `_remux_progress`).
- Config constants `UPPER_SNAKE` in config.py.
- Logging: `logging.getLogger("website")`, `basicConfig` format
  `"%(asctime)s %(levelname)s %(message)s"` with `datefmt="%H:%M:%S"`; per-job
  log lines prefixed `[<job_id>]`; timing logs `"[%s] Phase 2 done in %.1fs"`.
- Cleanup pattern (repeated everywhere): `try: if os.path.exists(p): os.remove(p)
  except OSError: pass`.
- **Progress callbacks are best-effort**: every invocation is wrapped in
  `try/except Exception: pass` — a throwing callback must never abort a render.
- Services raise `ValueError` for bad inputs, `RuntimeError` (with ffmpeg stderr
  tail) for ffmpeg failures; app.py converts exceptions into `status:"error"`.
- Imports: `import config` (absolute module name; run from the `website` dir so it
  resolves), `from services import media` (package-relative via `services/__init__.py`).

### JavaScript (templates/index.html)

- Vanilla ES2017+ (async/await, fetch, Promise, pointer events, Path2D); no
  libraries besides face-api.
- Element IDs camelCase (`faceSvg`, `faceImage`, `faceOvalHit`, `generateButton`,
  `moveX`...); CSS classes kebab-case (`step-btn`, `video-active`, `unmute-hint`).
- Client logs prefixed `"[face-guide]"` (`console.log/error/warn`).
- `update()` is the single source of truth for the SVG transform
  (zoom/moveX/moveY/rotate → width/height/x/y/rotate about center); sliders, step
  buttons, drag, and wheel all funnel through it.
- Transform consistency rule (**Observed**, critical): `update()`,
  `snapTransform()`, and the `getFacePngBlob()` canvas export all encode the same
  transform math (cover-fit `xMidYMid slice`, rotation about the box center).
  Change them together.
- Guide alignment constants: `EYE_GUIDE_Y = 168·0.438`, `MOUTH_GUIDE_Y = 168·0.767`
  must match CSS `.guide.eye { top: 43.8% }` / `.guide.mouth { top: 76.7% }`
  (commented in code).
- Slider ranges: zoom 0.1–30 (step 0.01), moveX/moveY −3000..3000 (step 1),
  rotate −180..180 (step 1); step-button nudge sizes `STEP_BY_CONTROL`
  {zoom: 0.05, moveX: 10, moveY: 10, rotate: 1}.
- Mobile/touch patterns (**Documented** in comments): `#faceOvalHit` has
  `touch-action: none` (drag target), `svg.face-svg` has `touch-action: pan-y`;
  step-button hover/press states are class-driven (`is-hover`/`is-press`) because
  CSS `:hover`/`:active` stick after taps on mobile; `DRAG_THRESHOLD = 6` px to
  let vertical pans scroll.
- `prefers-reduced-motion: reduce` kills all animations (**Documented**).
- iOS sound: `primeAutoplay()` must run **synchronously inside the click handler**
  (plays `static/silent.mp4` in the result `<video>` to unlock unmuted autoplay);
  fallback chip `#unmuteHint` for muted playback.

### Error Handling / Validation

- Server: 400 missing file / non-PNG; 413 oversized (Werkzeug
  `RequestEntityTooLarge` handler); 429 busy; 404 unknown job; 409 still
  rendering; 500 render/thread errors. JSON bodies `{"error": ...}`.
- Browser: friendly messages parsed from JSON error bodies; status element turns
  red (`#status.error`); `failRender()` re-enables the button.
- PNG magic-byte check is the only content validation (client produces the PNG);
  anything else is rejected.

## Required Validation Before Completion

- Renders must be 568×320 @ 24 fps with AAC audio (ffprobe check above).
- Phase-3 tuning regressions: check dark areas stay opaque (raise

  (raise `ERODE_ITERATIONS`).

## Important Files

### `app.py`

**Purpose**: Flask app — routes, in-memory job registry, background render thread,
progress + ETA bookkeeping, console logging.

**Important symbols**

- `app` (Flask instance; `MAX_CONTENT_LENGTH = 20 MB`)
- Routes: `index()`, `health()`, `assets(filename)`, `generate()` (POST),
  `progress(job_id)`, `result(job_id)`
- `_update_job(job_id, **fields)` — job record update + ETA history maintenance
- `_estimate_eta(history, percent)` — LS-fit seconds-to-completion
- `_evict_old_jobs_locked()` — MAX_JOBS eviction (done/error only)
- `_make_progress_callback(job_id, phase, lo, hi, remux_phase, remux_target)` —
  maps service callbacks to percent ranges
- `_run_render(job_id, face_png, bg_preview, final_video)` — render thread
- Constants: `MAX_JOBS = 20`, `MAX_ACTIVE_RENDERS = 1`, `RENDER_BUSY_MESSAGE`,
  `ETA_HISTORY_WINDOW = 30.0`, `ETA_HISTORY_MAX = 200`

**Dependencies**: `config`, `services.composite`, `services.overlay`, Flask,
Werkzeug (RequestEntityTooLarge).

**Modification rules**

- Register a job under `jobs_lock` **before** starting the thread (first poll must
  never 404); remove the job if thread start fails (busy-check deadlock).
- Keep statuses in `{"starting","rendering"}` as the busy set everywhere it is
  counted (both gate checks in `generate()`).
- Keep the single-render cap; do not raise it without shared job state.
- `/api/result` deletes the file and job after serving — keep that one-shot
  semantics (Cache-Control no-store; Content-Disposition `inline` for in-page
  playback).

### `config.py`

**Purpose**: Central configuration — paths, video spec, render tuning knobs,

**Important symbols**

- Paths: `BASE_DIR`, `ASSETS_DIR`, `TEMPLATES_DIR`, `STATIC_DIR`, `UPLOADS_DIR`,
  `TMP_DIR`, `TRACKING_JSON`, `BG_VIDEO`, `FG_VIDEO`
- Video spec: `FPS = 24`, `WIDTH = 568`, `HEIGHT = 320`
- Phase-3 knobs: `BLACK_CUTOFF = 5`, `FEATHER_RANGE = 35`, `BLUR_KERNEL = (5,5)`,
  `ERODE_KERNEL = 3`, `ERODE_ITERATIONS = 1`, `ALPHA_SAFE = 0.05`

### `services/overlay.py`

**Purpose**: Phase 2 — animate the face PNG over `BG.mp4` using tracking data.

**Important symbols**

- `_load_tracking(track_json)` — BOM-tolerant JSON load → `{frame_no: item}`
- `_overlay(frame, png, x, y, scale_x, scale_y, rotation, opacity)` — composite
  one frame (rotated/scaled RGBA at center x,y); skips opacity ≤ 0
- `render_bg_preview(face_png, track_json, bg_video, output_video, tmp_dir,
  progress_callback=None)` — main entry; emits phase "overlay" per frame and
  "remux_bg" (0,1) before remux

**Behavior**: requires 4-channel face PNG (else `ValueError`); writes
`<base>_temp.mp4` then remuxes audio from `bg_video`; cleans temp in `finally`.

**Modification rules**

- Keep the `-rotation` sign flip (AE CW vs OpenCV CCW).
- Skip frames with `opacity <= 0` before compositing.
- `scaleX`/`scaleY` are percentages (divide by 100).

### `services/composite.py`

**Purpose**: Phase 3 — brightness-matte composite of fg over bg.

**Important symbols**

- `render_final(bg_video, fg_video, output_video, tmp_dir, progress_callback=None)`
  — main entry; emits phase "composite" per frame and "remux" (0,1) before remux

**Behavior**: per-frame matte pipeline (brightness → clip → blur → erode → blur →
un-multiply → composite), tolerates fg/bg size mismatch by resizing fg; remuxes
audio from bg video.

**Modification rules**

- Tune via `config.py` knobs, not inline values.
- Keep the un-multiply floor (`alpha_safe`) to avoid black-contamination blow-up
  (division by ~0 alpha).

**Modification rules**

- Command args are fixed constants from config — never interpolate user input.
- `-progress pipe:1` parsing is required by the UI progress model; keep it.

**Purpose**: Entire front end — landing page, face-guide editor, canvas PNG

**Modification rules**

- Keep the transform trio (`update()` / `snapTransform()` / canvas export) in sync.
- Keep `PHASE_LABELS` keys matching server phase names: `overlay`, `composite`,

- Keep guide geometry (clipPath path, oval path, eye/mouth percentages, SVG

- `primeAutoplay()` must stay synchronous in the click handler.
- Do not add framework/build tooling without also restructuring `static/` — the

- **No authentication/CSRF**: the site is a public single-purpose generator;
